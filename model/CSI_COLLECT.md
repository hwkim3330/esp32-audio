# CSI 학습 데이터 수집 방법

음성은 Supertonic 으로 공짜로 합성했지만 **전파는 실측이 필요하다.** 이게 이 방향의
유일한 비용이고, 사람이 해야 하는 유일한 일이다.

## 왜 라벨이 '위치' 인가

CSI 는 AP↔보드 사이 전파 경로를 본다. 사람이 어디 서 있느냐에 따라 반사·회절 경로가
바뀌므로 패턴이 완전히 달라진다. 그게 약점이면서 기능이다:

- **약점** — 보드를 옮기거나 AP 가 달라지면 학습한 모델이 안 통한다. 다시 모아야 한다.
- **기능** — 같은 기하 안에서는 **위치를 구분할 수 있다.** 마이크 2개가 죽어서
  포기했던 좌/우 구분을 이걸로 되찾는다.

단, ESP32 는 안테나가 하나라 **진짜 도래각(AoA)은 못 낸다.** 위치별 지문(fingerprinting)
이고 학습한 위치에서만 통한다. 그걸 알고 쓰는 것과 모르고 쓰는 것은 다르다.

## 준비

보드에 `firmware/csi_logger` 를 굽는다. 라벨은 **보드 버튼**으로 찍으므로 PC 앞에
앉아 있을 필요가 없다.

| 버튼 | 라벨 | 비고 |
| --- | --- | --- |
| K1 | 빈 방 | 사람이 없는 상태 |
| K2 | 왼쪽 | 보드 기준 왼쪽에 서 있기 |
| K3 | 가운데 | 정면 |
| K4 | 오른쪽 | 오른쪽 |
| K5 | 이동 중 | 걸어 다니기 |
| K6 | 라벨 없음 | 폐기 (실기에서 K6 은 배선 이상으로 비활성될 수 있다) |

## 수집

```bash
python3 model/scripts/collect_csi.py --seconds 300 --tag session1
```

5분 세션 하나를 이렇게 쓰면 된다:

1. **K1 누르고** 방에서 나가 1분 (빈 방)
2. **K2 누르고** 왼쪽에 서서 1분 (조금씩 자연스럽게 움직여도 된다 — 고정된 자세만
   학습하면 실사용에서 안 통한다)
3. **K3 누르고** 가운데 1분
4. **K4 누르고** 오른쪽 1분
5. **K5 누르고** 1분 동안 걸어 다니기

**같은 세션을 2~3번, 가능하면 다른 시간대에** 하는 게 좋다. WiFi 트래픽 양과 주변
사람이 바뀌므로, 한 세션만 쓰면 그 순간의 조건에 과적합된다.

## 실측 참고값 (2026-08-05, 이 방)

```
#SCAN ch1=123 ch6=38 ch11=140     → 채널 11 선택
프레임 303, 서브캐리어 64, 10.1 Hz, 버림 0, seq 결손 0
진폭 평균 15.9  표준편차 11.7  RSSI -61 dBm
```

- **10 Hz 는 낮다.** 주변 WiFi 트래픽에 전적으로 의존한다. 사람이 많은 시간대나
  공유기 근처에서 하면 올라간다(같은 방에서 채널에 따라 4~268 Hz 로 흔들렸다).
- **서브캐리어 64개.** HT 패킷이 섞이면 128개도 오는데, 수집 스크립트가 최빈값만
  남긴다(섞이면 학습이 안 된다).
- 채널 탐색이 처음엔 망가져 있었다 — 콜백에서 `total++` 이 큐 검사 뒤에 있어서
  '트래픽' 대신 '큐 용량' 을 재고 세 채널이 모두 14 로 나왔다. 지금은 고쳤다.

## 데이터 형식

`model/data/csi/csi_<tag>.npz`

| 키 | 형태 | 내용 |
| --- | --- | --- |
| `amp` | (N, 64) float32 | 서브캐리어별 진폭 = sqrt(I²+Q²) |
| `iq` | (N, 128) int8 | 원시 (imag, real) 쌍 — 위상까지 쓰려면 이걸 쓴다 |
| `label` | (N,) uint8 | 0~4, 255 = 라벨 없음 |
| `rssi` | (N,) int16 | dBm |
| `ms` | (N,) uint32 | 보드 millis — 프레임 간격 계산용 |
| `seq` | (N,) uint16 | 큐에 들어간 프레임의 순번 |

## 그다음 — 학습 파이프라인을 그대로 재사용한다

CSI 시계열을 창으로 자르면 **(시간 × 서브캐리어) 행렬**이 된다. 그게 `model/` 의
인코더가 먹는 멜 스펙트로그램 **(192 × 40)과 같은 모양**이다. 즉 `train.py` 의
구조를 거의 그대로 쓸 수 있고, 그 추론 경로는 이 보드에서 이미 검증됐다 —
numpy 참조와 **오차 1.27e-07** 일치(`firmware/cabin_node/README.md`).

바꿔야 할 것은 프런트엔드뿐이다: 로그멜 대신 CSI 진폭 창을 넣고, 발화 단위 평균
차감 대신 **서브캐리어별 기준선 차감**을 한다(안테나·경로별 상수 오프셋을 지운다).
