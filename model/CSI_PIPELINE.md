# CSI 파이프라인 — 사람 라벨 없이 끝단까지 검증

오디오가 죽은 보드에서 온디바이스 감지를 하려면 CSI 학습 파이프라인이 필요하다.
그런데 위치 라벨은 사람이 움직여야 생긴다. 그래서 **사람 없이 검증 가능한 라벨원**을
찾아 배관부터 확인했다.

## 왜 채널을 라벨로 썼나

처음엔 **송신 AP** 를 라벨로 쓰려 했다. AP 마다 위치가 달라 다중경로가 다르니 사람
위치와 같은 구조의 기하 지문 문제가 된다. 그런데 실측에서 **한 MAC 이 98.1%** 를
차지했다(`32:cd:a7:ec:36:bf`, 로컬 관리 비트가 켜진 랜덤 MAC — 폰 핫스팟이나 클라이언트).
클래스가 안 갈려서 폐기했다.

**채널**로 바꿨다. 내가 명령할 수 있어 균형을 잡을 수 있고, 채널이 다르면 주파수
응답이 계통적으로 다르므로 진짜 다중클래스 문제다.

## 결과

```
데이터: csi_ch_auto.npz  창 434개  ch1:207 ch6:97 ch11:130
시간 분할: 학습 303 / 테스트 131 (각 세션 앞 70% / 뒤 30%)

파라미터   18.8K   추론 1.25M MAC
테스트     1.0000   (다수 클래스만 찍기 = 0.4130)
입력       64 프레임 × 64 서브캐리어
혼동 행렬: 대각선만 (28/38/26), 오분류 0
```

**100% 를 과대평가하면 안 된다.** 채널 분류는 원래 쉽다 — 채널이 다르면 주파수
서명이 계통적으로 다르니 모델은 그것만 배우면 된다. 사람 위치처럼 미묘한 차이를
구분하는 것과 난이도가 다르다. 이 숫자가 증명하는 것은 **배관이 맞다는 것**이고,
애초에 그게 목적이었다.

부수 결과: **18.8K 파라미터, 1.25M MAC** — 음성 모델(69.4K, 8.14M)보다 훨씬 작다.
실측 3.3 MMAC/s 로 환산하면 약 380ms 이고, 활성값을 내부 DRAM 으로 옮기면 더 줄어든다.

## 3단계 수치 검증이 CSI 에서도 이어진다

| 단계 | 비교 | 측정된 오차 |
| --- | --- | --- |
| BN 폴딩 | torch 원본 ↔ numpy 참조 | **2.533e-07** |
| C 이식 | numpy 참조 ↔ gcc 로 컴파일한 `cn_infer.c` | selftest **2.235e-07** |
| 임베딩 정규화 | L2 노름 | **1.000000** |
| 프로토타입 매칭 | `cn_match()` | 동작 (클래스 0, 코사인 0.5937) |

**추론 엔진을 복제하지 않았다.** `cn_infer.c` 하나를 두 프런트엔드가 공유한다 —
`model_data.h` 가 `CN_N_FFT` 를 정의하면 로그멜이 컴파일되고, CSI 처럼 정의하지 않으면
빠진다(스크래치도 964KB → 960KB 로 줄어든다). 파일을 복제하면 두 곳이 갈라지고,
갈라진 것은 나중에 못 찾는다. **음성 모델이 회귀 없이 통과함**을 같이 확인했다(1.490e-07).

## 프런트엔드 — CSI 에만 있는 문제 세 가지

`model/scripts/csi_features.py`

**1. 불균일한 샘플링.** CSI 는 주변 트래픽이 올 때만 생긴다 — 같은 방에서 채널에 따라
**4~268 Hz** 로 흔들렸다. 그래서 창을 프레임 수가 아니라 **시간으로** 자르고 고정
프레임 수로 리샘플한다. 프레임 수로 자르면 128프레임이 10Hz 에서 12.8초, 180Hz 에서
0.7초가 되어 모델이 보는 시간 폭이 매번 달라진다. (처음에 프레임 기준으로 짰다가
이 문제를 발견해 시간 기준으로 다시 썼다.)

**2. 서브캐리어별 상수 오프셋.** 안테나·경로·하드웨어 이득 때문에 서브캐리어마다 평균
진폭이 다르다. 음성의 발화 단위 평균 차감에 해당하는 것이 여기서는 **서브캐리어별
중앙값 차감**이다. 평균이 아니라 중앙값을 쓰는 이유는 평균이 사람이 지나간 큰 변화에
끌려가기 때문이다.

**3. 죽은 서브캐리어의 로그 폭주.** `first_word_invalid` 로 진폭이 0 인 빈에 로그를
씌우면 `log(1e-3)` 이 되고, 정규화 후 **-27** 까지 튀었다(실측). 죽은 빈 몇 개가 전체
분포를 지배하면 학습이 그쪽에 끌려간다. ±6 으로 클리핑해 막았다.

## 실기에서 잡은 버그

**채널 순환이 첫 전환 후 영구 정지했다.** 버튼 우선 판정을 `cur_label` 값으로 했는데,
자동 라벨이 `cur_label=1` 을 넣자마자 다음 루프가 그걸 "버튼이 눌렸다"로 오인했다.
60초간 라벨 1 고정이었다. 버튼 눌림은 `keys_poll` 에서 따로 표시해야 한다.

**채널 탐색이 트래픽 대신 큐 용량을 재고 있었다.** 콜백의 `total++` 이 큐 검사 뒤에
있어서, `delay()` 로 루프가 멈춘 동안 큐가 차면 `total` 이 안 늘어난다. 세 채널이 모두
14 로 나왔다. 고친 뒤 `ch1=129 ch6=128 ch11=56` 으로 갈리고 RSSI 가 -79 → -61 로 개선됐다.

**`np.frombuffer` 를 `bytearray` 에 직접 걸었다.** 뷰가 export 로 남아 버퍼를 줄이는
`del` 이 `BufferError` 를 냈다. 슬라이스를 `bytes()` 로 복사해 해결.

## 조사 — 현재 수준 (2026-08)

- **IEEE 802.11bf-2025** 가 2025-09-26 정식 발행됐다. WiFi 센싱이 표준이 됐고,
  6GHz 이하에서 bistatic·multistatic 센싱을 규정한다.
- **ESP-Fi HAR** (2026-02) 이 ESP32 CSI HAR 벤치마크 데이터셋이다. 4환경 7동작,
  기준 모델 제공. 최고 백본은 **ResNet18**.
- ESP32 CSI 수집 도구가 **최대 180 패킷/초** 를 낸다. 우리 실측 10~22 Hz 는 한참 낮고,
  차이는 **능동 프로빙** 이다 — 프로브 요청을 쏘면 주변 AP 가 응답하며 CSI 가 급증한다.
  자격증명이 필요 없으므로 다음 개선 항목이다.
- 55KB 모델로 동작을 분류한 사례가 있다. 우리 18.8K 파라미터는 같은 급이다.


## 호흡 주기성 — 분산보다 강한 증거 (2026-08-10 측정)

우리 감지기는 "분산 비슷한 대역 점수 > 임계값" 하나다. 이 방식의 근본 한계는
**전파 환경이 사람 없이도 드리프트하고, 드리프트가 분산을 올린다**는 것이다. 그래서
빈 방 기준선을 아무리 모아도 오탐과 감지를 확실히 가를 수 없다.

주기성은 다르다. 드리프트는 분산을 올리지만 **일정한 주기를 만들지 않는다.** 그래서
"0.23Hz 에 뾰족한 봉우리가 창마다 같은 자리에 온다" 는 훨씬 강한 증거다. 그리고
**가만히 있는 사람**을 잡을 수 있다 — 분산 방식이 실패하는 바로 그 경우다. K1 검증은
걸어다녀야 하므로 쉬운 쪽(움직임)만 확인한다.

굽기 전에 오프라인으로 확인했다(`model/scripts/csi_rate_probe.py`). 남의 공개
녹음(ruvnet/RuView, MIT, 밤샘 51분, ESP32-S3 2노드, 서브캐리어 64개 — 우리와 같은 폭)을
빌렸다. 자는 사람이 방에 있다는 것만은 신뢰할 수 있는 데이터다.

```
                           뾰족함   백색널   지배bpm  일관성  대역최저칸
RuView 밤샘 node1           31.6     4.3     14.0    100%      0%
RuView 밤샘 node2           30.9     4.3     14.0     96%      0%
우리 csi_ap_auto (빈 방)     5.1     4.8     19.0     25%     12%
합성 랜덤워크(드리프트 널)    27.1       —      6.0    100%     62%
```

읽는 법이 중요하다. **대역대비만 보면 안 된다** — 랜덤워크 널의 대역대비가 실제
데이터보다 높다(6.2 대 1.2). 드리프트는 1/f² 스펙트럼이라 저주파에 에너지가 쏠리기
때문이다. 판별자는 두 개를 같이 봐야 한다: **일정한 bpm 에 반복되는 뾰족한 봉우리**
이면서 **대역 최저 칸에 쌓이지 않는 것**. 드리프트는 최저 칸(6bpm)에 62% 쌓인다.

우리 빈 방 데이터는 백색잡음 널과 구별되지 않는다(5.1 대 4.8). 사람이 없었으니
그래야 맞다 — 우리 하드웨어에 대한 부정적 결과가 아니다.

### 대안 가설 두 개를 기각했다

14bpm = 4.3초 주기다. 무언가 4.3초짜리 시스템 동작이 있을 수 있으므로 확인했다.

- **샘플링/클럭 인공물이 아니다.** 진폭 대신 **패킷 도착 간격** 시계열을 같은 방식으로
  분석하면 지배 bpm 중위 17.0, 일관성 16%, 뾰족함 4.5(= 백색잡음 수준)다. 14bpm 근처
  창은 7% 뿐이다. 시계에는 그 주기가 없다.
- **주파수 선택적이다.** 64개 중 **28개** 서브캐리어만 14bpm 을 뾰족하게 보고, 강한
  것들이 덩어리로 뭉친다(1–2, 12–20, 24–26, 39–42, 51–56). 클럭 인공물이면 64개 전부에
  고르게 실린다. 서브캐리어별로 갈리는 것은 다중경로 변조의 서명이다.

이 두 검정이 없으면 "봉우리를 봤다" 는 아무 뜻이 없다. 우리가 앞서 OOD 프로토타입
은행을 쉬운 평가셋 위의 극적인 숫자만 보고 채택할 뻔했다 — 같은 실수를 반복하지 않으려고
널 두 개(백색·랜덤워크)와 대안 가설 두 개를 먼저 세웠다.

### 우리 보드에 필요한 조건 — 채널 고정

창 길이를 훑어서 최소 요건을 정했다(RuView 데이터, 10Hz 리샘플):

```
   창     뾰족함   백색널    지배bpm   일관성
 120s      70.1     5.5      14.0     100%
  60s      31.6     4.3      14.0     100%
  45s      19.0     3.9      14.7     100%
  30s      12.6     3.5      14.0      92%   ← 실용 하한
  20s       6.9     3.0      15.0      70%   ← 경계
  15s       4.3     2.3      16.0      48%   ← 무너진다
```

**같은 채널에서 30초 이상 연속**이 필요하고 45초면 확실하다. 그런데 우리 펌웨어는
추론 헛돌기를 줄이려고 채널 체류를 10초로 잡았다(`radar_display`). 10초 창은 일관성
67% 에 지배 bpm 이 12.0 으로 흘러 쓸 수 없다. **즉 지금 구성으로는 호흡을 볼 수 없다.**

필요한 것은 새 기능이 아니라 이미 있는 것을 쓰는 것이다 — K4 길게 누르면 채널이 고정된다
(`ch_lock`). 호흡 탐침은 "채널 고정 + 45초 누적" 모드로 넣으면 되고, 계산은 자기상관이면
600표본에 18만 MAC 이라 FFT 도 필요 없다(참고로 음성 인코더가 1회 814만 MAC 이다).

### 자기상관은 안 된다 — 대역통과가 주기성을 만들어낸다

보드에는 FFT 대신 자기상관을 넣을 생각이었다. 360표본에 지연 범위 하나면 백만 MAC
대이고, 우리 `cn_infer.c` 의 FFT 는 CSI 빌드에서 아예 컴파일되지 않으므로(CN_N_FFT
미정의) 새로 들여올 이유가 없어 보였다. **틀렸다.** 같은 데이터로 재보니 실패한다.

세 번에 걸쳐 원인을 좁혔다.

1. 처음 지표가 망가져 있었다: 뾰족함을 `(봉우리 − 중앙값)/|중앙값|` 로 썼는데, 잡음이면
   자기상관 중앙값이 0 근처라 분모가 폭발한다. 백색잡음 널이 실제 데이터보다 높은
   값을 받았다(604 대 283). 정규화 자기상관의 봉우리 값 자체로 고쳤다.
2. 그래도 분리가 없었다(0.25 대 널 0.24). 대역통과를 건너뛴 탓이었다 — 선형 추세
   제거만으로는 0.1Hz **이하** 드리프트가 남아 자기상관 전 구간을 지배한다. RuView 가
   주기 탐색 앞에 biquad 를 둔 이유가 이것이다.
3. biquad 를 넣어도 안 된다(0.32 대 널 0.38). **여기가 핵심이다.**

**대역통과된 백색잡음은 협대역 신호이고, 협대역 신호의 자기상관에는 중심주파수 주기의
봉우리가 원래 있다.** 즉 대역을 자르는 행위 자체가 자기상관이 재려는 그 주기성을
만들어낸다. 그래서 ACF 봉우리 높이로는 호흡과 대역제한된 잡음을 구별할 수 없다.

FFT 쪽 지표는 그 함정에 안 걸린다. 뾰족함을 **대역 안에서의** 봉우리/중앙값으로 재기
때문이다. 진짜 단일 주기는 한 칸에 몰려 대역 중앙값을 훌쩍 넘지만, 대역제한된 잡음은
칸들에 퍼져서 봉우리와 중앙값이 붙는다. 대역통과는 대역 안 집중도를 만들어내지 못한다.

부수적으로 서브캐리어 선택 기준은 원인이 아님을 확인했다 — FFT 쪽은 대비/에너지/뾰족함
어느 것으로 골라도 14.0bpm·일관성 100% 가 나온다.

**그래서 보드에도 주기도(periodogram)를 넣는다.** 비용은 오히려 더 싸다: 60초 창을 8Hz
로 잡으면 480표본 → 512점 실수 FFT 가 약 14k MAC, 서브캐리어 64개에 0.9M MAC 이다.
싸 보였던 자기상관 판본이 1.6M MAC 이었고 게다가 틀렸다. 값싼 분산으로 상위 8개
서브캐리어만 먼저 골라 FFT 를 걸면 0.12M MAC 까지 내려간다.

### 곁가지로 확인된 것

같은 파일에서 RuView 자신의 파이프라인은 호흡을 **평균 24.9bpm**(최대 40), 심박 85.8 로
보고했고 `n_persons` 는 6,063 레코드 내내 4 로 고정, `presence_score` 는
`motion_energy` 와 6063/6063 완전히 같은 값이었다. 원시 데이터에는 14bpm 이 선명한데
그들의 추정기가 그것을 못 뽑았다. **데이터는 좋고 추정기가 나쁘다** — 그래서 그 레포의
숫자를 목표치로 삼으면 안 되고, 원시 녹음은 값지다.
