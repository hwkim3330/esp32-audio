# 캐빈 노드 — ESP32 온디바이스 음성 인식 모델

ESP32-Audio-Kit 이 사람 말을 알아듣게 만드는 초소형 모델. 학습은 3090 에서 1회,
런타임은 ESP32 단독 (PC 없음, 클라우드 API 없음, SD 카드 없음).

## 왜 이 구조인가

먼저 안 되는 것을 못 박아야 설계가 선다. **생성 모델은 4MB 플래시에 물리적으로
안 들어간다.** Supertonic 3 (TTS) 는 ONNX 총 398MB 고, int8 로 눌러도 100MB 급이다.
Whisper tiny 도 39M 파라미터다. TTS·STT·LLM 은 이 칩에서 두 자릿수 배율로 부족하다.

그런데 차 안 음성의 실제 효용 대부분은 자유 작문이 아니라 **의도 파악**이다.
그래서 이렇게 나눴다:

| 역할 | 어디서 | 무엇 |
| --- | --- | --- |
| 학습 데이터 합성 | PC (1회성) | Supertonic 3 — 한국어 발화 2,970개, 사람 녹음 0회 |
| **인식 (런타임)** | **ESP32** | 이 저장소의 인코더, 69.4K 파라미터 |
| 응답 음성 | 태블릿 또는 플래시 | 태블릿이 즉석 합성 → WiFi → PSRAM 캐시 / 또는 플래시의 ADPCM |

## 핵심 설계: 분류기가 아니라 임베딩

라벨을 **인텐트(27개)가 아니라 문장(93개)** 으로 두고 metric learning 을 한다.
인식은 마이크 임베딩과 등록된 문장 임베딩의 코사인 최댓값을 고르는 것뿐이다.

이유는 하나다. **새 명령 추가에 재학습이 필요 없어야 한다.** 인텐트 분류기로
학습하면 28번째 명령을 넣으려면 다시 학습해야 한다. 문장 단위로 "같은 말은 같은
벡터" 를 배우면, 새 문장은 임베딩 평균 한 번으로 등록된다 — ESP32 는 학습을 못 하지만
평균은 낸다.

그게 진짜 되는지 측정했다: 문장 27개를 학습에서 **완전히 제외**하고, 등록만으로
맞히는지 봤다.

## 측정 결과

RTX 3090, 120 에폭 3분. 보류 보이스 F5/M5 는 학습에 일절 쓰지 않았다.

| 지표 | 값 |
| --- | --- |
| 파라미터 | **69.4K** (float32 268KB) |
| 추론 1회 | **8.14M MAC** |
| 문장 정확도 — 학습된 문장, 처음 듣는 목소리 | **0.939** |
| **문장 정확도 — 학습에서 제외한 27문장** | **0.932** ← 재학습 없이 명령 추가가 되는지의 지표 |
| 인텐트 정확도 (93 프로토타입 → 27 인텐트) | **0.893** (498/558) |
| OOD 오수락 (명령 재현율 95% 기준) | **52.8%** ← 미해결, 아래 참조 |

`model/out/train.log`, `model/out/enroll_report.json` 에 원본이 있다.

### 도중에 틀렸던 것 두 개

기록해 둘 가치가 있어서 남긴다.

**1. 인텐트당 프로토타입 1개는 실패한다 (0.667).** 한 인텐트의 서로 다른 문장
("에어컨 켜줘" / "시원하게 해줘" / "냉방 켜줘") 을 평균했는데, 인코더는 애초에 다른
문장을 **멀리 떼어놓도록** 학습됐다. 그 평균은 어느 문장에도 가깝지 않은 헛점이 된다.
학습 목표와 등록 방식이 서로 싸운 것이다. 문장당 1개로 바꾸니 0.667 → **0.893**.

**2. 점수 정규화로 OOD 를 잡으려던 시도는 실패했다.** "도메인 내 발화는 자기
프로토타입만 튀고 OOD 는 고르게 닮을 것" 이라 보고 `top1-top2`, `top1-mean` 을
시험했다. 결과는 개선 없음(52.8% 동일) 또는 악화(91.7%). 가설이 틀렸다.

## 미해결: OOD 거부

**명령이 아닌 말을 절반 넘게 명령으로 받는다(52.8%).** 실사용에서 오작동으로 직결되는
문제라 그대로 적어 둔다.

원인은 학습 설계다. `train.py` 가 OOD 클립을 학습 라벨에서 제외했으므로(`cmd_items`
필터), 인코더는 "학습 문장 66개를 서로 떼어놓는 법" 만 배웠다. 처음 듣는 문장은 아무
데나 떨어지고, 프로토타입이 93개면 그중 하나와는 우연히 가깝다.

추정도 거칠다 — OOD 테스트가 36클립(고유 문장 12개)뿐이라 ±8% 수준이다.

해야 할 일:

1. **OOD 를 학습 클래스로 포함** — 명령에서 밀어내는 힘을 주는 원칙적 해법
2. **OOD 문장을 수백 개로 늘리기** — 현재 30개는 너무 적다
3. 호출어 게이트를 앞에 두어 상시 인식을 피하기 (실전 완화책)

## 파이프라인

```
commands.json                       27 인텐트 · 93 문장 · 응답 · 톤 프리셋
   ↓  gen_data.py                   Supertonic 3 으로 합성 (10 보이스 × 3 속도)
model/data/utterances/              2,970 클립 / 음성 75분 / 20분 소요 (RTF 0.267)
   ↓  train.py                      metric learning, 잔향·노이즈·마스킹 증강
model/out/encoder.pt                69.4K 파라미터
   ↓  enroll.py                     문장별 프로토타입 → prototypes.h
   ↓  export.py                     BN 폴딩 → model_data.h / model_weights.h / selftest.h
firmware/cabin_node/                ESP32 가 그대로 컴파일
```

### 재현

```bash
# 1) Supertonic 3 모델 (약 396MB)
pip install --break-system-packages supertonic
hf download Supertone/supertonic-3 --local-dir ~/supertonic-3-assets

# 2) 데이터 합성 (약 20분)
python3 model/scripts/gen_data.py --assets ~/supertonic-3-assets

# 3) 학습 (3090 에서 약 3분)
cd model/scripts && python3 train.py --epochs 120 --bs 64

# 4) 등록 + 내보내기
python3 enroll.py && python3 export.py

# 5) C 추론이 파이썬과 같은 값을 내는지 검증
cd ../.. && gcc -O2 -std=c99 -Ifirmware/cabin_node \
  model/scripts/parity_test.c firmware/cabin_node/cn_infer.c -lm -o /tmp/parity
/tmp/parity model/out/encoder.bin
```

## 수치 검증 — 보드에 올리기 전에 통과해야 하는 것

임베디드 추론에서 가장 흔한 실패는 "돌긴 도는데 값이 미묘하게 다름" 이고, 그건 데모
중에 **정확도 문제로 위장해서** 나타난다. 그래서 세 단계로 막았다.

| 단계 | 무엇을 비교 | 측정된 오차 |
| --- | --- | --- |
| BN 폴딩 | torch 원본 ↔ numpy 참조 구현 | 최대 1.49e-07 |
| C 이식 | numpy 참조 ↔ gcc 로 컴파일한 `cn_infer.c` | 임베딩 코사인 0.9999999 |
| 보드 자기검증 | 알려진 멜 입력 ↔ 알려진 임베딩 (`selftest.h`) | 부팅 시 자동, 허용 2e-3 |

`cn_infer.c` 가 ESP-IDF 에 의존하지 않는 순수 C99 인 이유가 이것이다 — 같은 파일을
gcc 로 컴파일해 PC 에서 검증할 수 있다.

## 왜 int8 이 아니라 float32 인가

ESP32 는 단정밀도 FPU 가 있고 **SIMD 가 없다.** int8 로 내려도 dot-product 명령이
없어서 속도 이득이 거의 없고, 양자화 오차만 생긴다. 메모리는 PSRAM 4MB 로 넉넉하다
(가중치 268KB + 활성값 약 490KB). 그래서 학습과 추론이 수치적으로 같아지는 float32 를
택했다. 속도가 부족해지면 그때 int8 을 얹는 것이 순서다.

## 자원 예산

| 항목 | 크기 | 어디 |
| --- | --- | --- |
| 인코더 가중치 | 268KB | 플래시 (`model_weights.h`, 메모리 매핑되어 복사 없음) |
| 프로토타입 93개 | 46.5KB | 플래시 (`prototypes.h`) |
| 활성값 핑퐁 버퍼 | 480KB | PSRAM |
| FFT 작업 버퍼 | 4KB | PSRAM |
| 멜 필터뱅크 | 468 계수 | 플래시 — 40×257 중 0 아닌 것만, 프레임당 MAC 을 10,280 → 468 로 줄인다 |

## 미확인 항목

- **보드 핀 배치** (`firmware/cabin_node/board_pins.h`) — 실크스크린을 읽지 않고
  소프트웨어로만 식별했다. AC101 I2C 프로브로 런타임에 검증하게 해 뒀지만, 실물
  확인 전에는 가정이다.
- **온보드 실측 추론 시간** — 8.14M MAC 에서 200~400ms 로 추정하지만 측정하지 않았다.
  보드에 굽지 않았다 (공장 펌웨어가 아직 살아 있고, 덮어쓰기 전에 확인이 필요하다).
- **실제 마이크 인식률** — 위 숫자는 전부 합성 음성 기준이다. 잔향·노이즈 증강을
  넣었지만 실제 캐빈 마이크 성능은 별개다.
