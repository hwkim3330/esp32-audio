# 신스 노드 — ESP32-Audio-Kit 을 악기로

보코더 · 신스 · 딜레이 · 루퍼. 마이크에 말하면 신스가 말한다.

## 화면 없는 문제를 소리로 푼다

이 보드에 화면이 없어서 "동작하는지 알 수 없다" 는 게 실제 문제였다. 악기는 그걸
구조적으로 해결한다 — 말하면 소리가 바뀌어 나오니 확인이 필요 없다. 여기에 두 개를 더 했다.

1. **부팅 진단음.** 상승 4음(C-E-G-C′, 0.48초)을 낸다. 들리면 **코덱·I2S·앰프·스피커가
   전부 정상**이라는 증거다. 안 들리면 그 경로 어딘가가 죽은 것이다. 화면 대신이다.
2. **조작마다 다른 확인음.** 모드·파형·옥타브·루퍼가 각각 다른 음을 내므로 지금 무슨
   상태인지 귀로 안다.

## 버튼 6개 전부 — 짧게 연주, 길게 조작

| 키 | 짧게 | 길게 (600ms) | 아주 길게 (2s) |
| --- | --- | --- | --- |
| K1 (GPIO19) | 도 | 모드 순환 (보코더→신스→딜레이) | |
| K2 (GPIO23) | 레 | 파형 순환 (톱니→사각→펄스→삼각) | |
| K3 (GPIO18) | 미 | 옥타브 − | |
| K4 (GPIO5) | 솔 | 옥타브 + | |
| K5 (GPIO36) | 라 | 루프 녹음/확정/오버덥 | **루프 지우기** |
| K6 (GPIO13) | 도′ | 루프 지우기 | |

펜타토닉 6음이라 아무 조합을 눌러도 불협이 안 난다 — 화면 없이 즉흥 연주하려면 이게 안전하다.

**K6 는 실기에서 배선 불량으로 확인됐다** (아래 참조). 그래서 '지우기' 를 K5 2초 누름으로
옮겼다. 키 하나가 죽어도 기능은 잃지 않는다.

## 실기 측정 결과 (2026-08-05, 실제 보드)

```
=== 신스 노드 ===
[probe] AC101 응답 있음
[keys] 부팅 스캔: K1(GPIO19)=1 K2(GPIO23)=1 K3(GPIO18)=1 K4(GPIO5)=1 K5(GPIO36)=1 K6(GPIO13)=0[비활성]
[keys] 사용 가능 5/6
루퍼/딜레이 버퍼 3.9 MB = 63.5초
부팅 진단음 재생 (15360 샘플쌍)
모드 보코더, 파형 톱니, 옥타브 +0
```

빌드: 367KB (11% of 3MB), DRAM 7%. 캐빈 노드(97%)와 달리 아주 가볍다.

### 실기에서 잡은 버그 두 개

**1. K6(GPIO13)이 안 눌렀는데 LOW.** K1~K5 는 정상인데 K6 만 그렇다. 핀 가정이 틀렸거나
다른 게 물려 있다. 이대로 두면 '루프 지우기' 가 계속 발동해서 악기가 아예 동작하지 않는다.
그래서 **부팅 스캔으로 LOW 인 키를 자동 비활성화**하게 했다 — 핀 가정이 틀려도 조용히
오작동하지 않고, 무엇이 죽었는지 알려준다.

**2. `LoadStoreError`, EXCVADDR `0x400918e4` — IRAM 에 16비트 접근.**
`heap_caps_malloc(..., MALLOC_CAP_INTERNAL)` 이 **IRAM** 을 돌려줄 수 있고, IRAM 은
바이트·16비트 접근이 불법이다. I2S 버퍼를 `int16_t*` 로 읽는 순간 죽는다.
I2S 버퍼는 `MALLOC_CAP_DMA` 로 잡아야 한다 — 8비트 접근이 보장되고 DMA 도 닿는다.

## 설계 결정

**보코더를 FFT 가 아니라 시간영역 필터뱅크로 만들었다.** FFT 보코더는 윈도잉·오버랩애드·
위상 처리가 붙고 지연이 프레임 단위로 생긴다. 16밴드 바이쿼드 뱅크는 샘플당 약 64 MAC
이라 32kHz 에서 2 MMAC/s 뿐이고, 지연이 사실상 0 이며 소리는 오히려 더 클래식하다.
밴드는 200Hz~6.4kHz 로그 간격, Q=3, 포락선 시간상수 12ms.

치찰음(ㅅ, ㅊ)은 밴드 에너지가 낮아 보코더만 쓰면 발음이 흐려진다. 그래서 마이크의 5kHz
이상을 그대로 35% 섞는다 — 자음 명료도가 살아난다.

**PSRAM 은 순차 접근에만 쓴다.** 캐빈 노드에서 추론이 2455ms 나온 원인이 PSRAM 랜덤
접근이었다(README 참조). 그래서 DSP 상태는 전부 내부 DRAM 전역 변수로 두고, PSRAM 은
딜레이/루퍼 버퍼처럼 순차로만 읽는 것에 준다. 3.9MB = **63.5초 루퍼**가 여기서 나온다.

**펜타토닉 + 폴리 6음.** 보이스마다 0.4% 씩 디튠해 유니즌 두께를 만들고, 톱니·사각·펄스에
PolyBLEP 을 걸어 에일리어싱을 줄였다.

## 자원 사용

| 자원 | 쓰는 것 |
| --- | --- |
| 플래시 | 367KB (11%) — 여유가 많다. 웨이브테이블/샘플을 넣을 자리 |
| **PSRAM** | **3.9MB (거의 전부)** — 63.5초 루퍼/딜레이 |
| 내부 DRAM | 7% — DSP 상태 전부 (의도적으로 여기 둔다) |
| 코어 1 | 오디오 태스크 (블록 256샘플 = 8ms) |
| 코어 0 | 키 폴링 (`loop()`) |
| 마이크 2개 | 합쳐서 모듈레이터 (한쪽만 쓰면 3dB 손해) |
| 스피커 | DAC + 앰프 상시 ON |
| 터치키 | 5/6 (K6 배선 불량) |

## PC 검증

`sn_dsp.c` 는 ESP-IDF 에 의존하지 않는 C99 라 gcc 로 컴파일해 측정할 수 있다.

| 항목 | 결과 |
| --- | --- |
| 밴드패스 선택도 | 1kHz 0.500 / 250Hz 0.0039 / 4kHz 0.0035 → 약 128배 |
| 보코더 게이팅 | 무음 0.000000 / 발성 0.004985 |
| 발진기 주파수 | 440Hz 지정 → 440.0Hz 측정 |
| 딜레이 탭 | 임펄스 → 정확히 4000 샘플, 진폭 1.000 |
| 루퍼 | 1000샘플 루프 → 3000샘플에 3회 정확 반복 |

## 빌드

```bash
arduino-cli lib install --git-url https://github.com/Yveaux/AC101   # GPL-3.0 주의
arduino-cli compile --fqbn \
  'esp32:esp32:esp32:PSRAM=enabled,FlashSize=4M,PartitionScheme=huge_app,CPUFreq=240' \
  firmware/synth_node
arduino-cli upload -p /dev/ttyUSB0 --fqbn '...,UploadSpeed=460800' firmware/synth_node
```

## 아직 안 한 것

- **소리를 들어보지 않았다.** 위 측정은 전부 수치이고, PC 에 블루투스도 스피커 판단
  수단도 없다. 실제로 좋게 들리는지는 확인이 필요하다.
- **K6 의 진짜 핀 미확인.** GPIO13 이 아니다. 후보 GPIO 를 순회하며 눌린 것을 찾는
  탐색 스케치가 필요하다.
- **BLE-MIDI 없음.** 태블릿이 건반이 되는 경로. PSRAM·플래시 여유가 많아 넣을 자리는 있다.
- **A2DP 없음.** 악기 출력을 블루투스 스피커로 보내거나 반주를 받는 용도.
- **배터리 모니터 없음.** 휴대 악기라면 잔량 표시가 필요하다.
- **I2C OLED 미장착.** GPIO32/33 I2C 는 실기 검증됐으므로 SSD1306 을 같은 버스에 물리면
  핀 추가 0 으로 화면이 생긴다. 부품이 있으면 바로 붙일 수 있다.
