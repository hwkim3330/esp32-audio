# Gicisky BLE 전자종이 태그 라이브러리

아무 ESP32 에서 도는 독립 라이브러리다. 파일 두 개(`esl_bwr.h`, `esl_bwr.cpp`)만
복사하면 끝이고, 이 저장소의 센싱 코드와 아무 관계가 없다.

```
esl_lib/
├── esl_bwr.h        드라이버 인터페이스
├── esl_bwr.cpp      구현 (모델 표 11개 포함)
├── example/         최소 예제 스케치
└── README.md        이 문서
```

## 5분 안에 돌리기

**필요한 것**

- Arduino ESP32 코어 (3.x 확인). **Bluedroid BLE** — NimBLE 아니다(아래 참고)
- `Adafruit GFX Library`
- `U8g2_for_Adafruit_GFX` (한글이나 다양한 폰트를 쓸 때만)

**최소 코드**

```cpp
#include <BLEDevice.h>
#include <Adafruit_GFX.h>
#include "esl_bwr.h"

EslTag tags[ESL_MAX_TAG];
GFXcanvas1 bw(ESL_W, ESL_H), red(ESL_W, ESL_H);
uint8_t buf[ESL_BYTES];                 // 9472바이트 — PSRAM 권장

BLEDevice::init("");
int n = esl_scan(tags, ESL_MAX_TAG, 8); // 광고에서 모델까지 읽어온다
esl_warmup(tags[0].addr);               // 첫 전송의 21초 손해를 여기서 소진

bw.fillScreen(1);                       // 1 = 흰색
red.fillScreen(1);                      // 1 = **적색 없음** (극성이 반대다)
bw.setCursor(4, 20); bw.print("hello");

size_t len = esl_pack(tags[0], bw, red, buf);
esl_upload(tags[0].addr, buf, len, nullptr, nullptr);
```

**MAC 을 코드에 적지 않는다.** 광고에서 모델·전압·펌웨어까지 읽으므로 태그를 바꿔
끼워도 코드를 안 고친다. 참조 구현들은 MAC 을 배열에 박아두는데, 그러면 BW 모델에
BWR 페이로드를 보내 화면이 깨지는 일이 생긴다.

## 가장 효율적인 갱신 방법

측정에서 나온 순서다. **위쪽이 압도적으로 크다.**

### 1. 안 바뀌면 안 보낸다 — 10~20배

전자종이는 **이미지 유지에 전력이 0** 이다. 같은 그림을 다시 굽는 것은 순수한
낭비다 — 배터리도, 3.5초도, 잔상도.

라이브러리가 태그별로 마지막에 보낸 페이로드 해시(FNV-1a)를 기억하고 같으면
`ESL_SKIPPED` 를 돌려준다. 연결조차 하지 않는다.

그리고 **호출 자체를 사건에 걸어야 한다.** 타이머로 부르면 해시가 걸러주긴 하지만
스캔과 판단 비용은 계속 든다. 실측 비교:

| 방식 | 태그당 하루 갱신 |
|---|---|
| 90초 타이머 | **960** |
| 사건 기반 + 최대 정체 30분 | **50~100** |

태그는 소매점 가격표용으로 **하루 몇 번** 갱신 전제로 설계됐다. 코인셀 하나로 몇 년
버티는 것이 정상이고, 타이머로 굽으면 며칠에 끝난다.

### 2. 부팅 후 첫 전송을 미리 소진한다 — 6배 (첫 화면에 한해)

**부팅 후 첫 전송만 파트 크기를 20 으로 협상한다.** 그러면 592파트 / **21초**가
걸린다. 두 번째부터는 244 를 줘서 40파트 / **3.5초**다. 세션 특성이라 같은 연결
안에서 다시 물어봐도 안 바뀌고, 재연결이 필요하다.

`esl_warmup(addr)` 이 부팅 직후에 연결·협상만 하고 끊는다. 사람이 볼 첫 화면이
21초 걸리는 것과 버리는 세션이 21초 걸리는 것은 완전히 다른 일이다.

### 3. 적색을 빼도 빨라지지 않는다 — 0배 (하지 말 것)

당연해 보이는 최적화인데 **측정으로 기각됐다.** 적색 평면을 빼면 페이로드가
9472 → 4736 바이트, 파트가 40 → 20 이 된다. 같은 환경에서 회차마다 번갈아 재봤다.

| | 바이트 | 파트 | 평균 |
|---|---|---|---|
| 흑백+적색 | 9472 | 40 | **4074ms** (11회) |
| 흑백만 | 4736 | 20 | **4327ms** (8회) |

**차이가 없다.** 병목이 BLE 바이트가 아니라 **연결 수립 + 태그 자신의 전자종이
리프레시**다. 그건 내용량과 무관하게 몇 초 걸린다.

그리고 더 중요한 함정: **적색 평면을 안 보내는 것은 적색을 끄는 것이 아니다.**
전자종이는 잔류형이라 적색 레이어가 지워지지 않고 이전 내용이 그대로 남는다.
흑백만 보내면 예전 적색이 **박제된다**(실기에서 화면이 계속 빨갰다). 적색을 없애려면
적색 평면을 **흰색(=1)으로 채워서 함께 보내야** 한다.

결론: **적색은 속도 문제가 아니라 가독성 선택이다.** 필요하면 쓰고, 안 쓸 거면
빈 평면을 함께 보내라.

### 4. 여러 태그를 한 세션에 몰아서 — 연결 비용이 지배적이다

연결 수립이 시간의 대부분이므로, 사건 하나에 태그 넷을 각각 다른 시점에 굽는 것보다
한 번에 몰아 굽는 것이 낫다. 다만 `BLEClient` 는 하나만 쓰고 태그 사이에
`disconnect()` + 600ms 를 둔다(아래 함정 참고).

### 5. 필요 없을 때 스캔하지 않는다

`esl_scan(secs)` 은 그 시간 동안 BLE 스캔을 독점한다. 갱신할 태그가 없으면 스캔도
하지 말 것. 주소는 지난 스캔 결과에 남아 있으므로 판단은 스캔 없이 할 수 있다.

### 6. 전압 하한을 둔다

**2.35V 아래로는 굽지 않는다.** 낮은 전압에서 전자종이를 구동하면 부분만 바뀌어
화면이 깨지고 셀도 더 상한다. 전압은 광고에 실려 오므로 연결 없이 읽힌다.

측정 예(2.9인치 4대, 정상 상태): **2.7~2.8V**. 모델 표의 범위가 2.2~3.0V 이니 약 69%.

## 반드시 피해야 하는 함정

### `delete cli` 하면 죽는다

전송마다 `createClient` / `delete` 를 하면 매번 이 자리에서 죽는다.

```
assert failed: xQueueGenericSend queue.c:937
BLEClient::gattClientEventHandler → ESP_GATTC_DISCONNECT_EVT
  → m_semaphoreOpenEvt.give(ESP_GATT_IF_NONE)      (BLEClient.cpp:535)
```

끊김 이벤트가 `delete` **뒤에** 도착해서 해제된 객체의 세마포어를 건드린다.
Bluedroid 가 클라이언트 포인터를 계속 들고 있으므로 우리가 먼저 지우면 안 된다.
이 라이브러리는 **클라이언트 하나를 만들어 재사용하고 절대 삭제하지 않는다.**
객체 하나가 새지만 태그 여러 대를 돌려 쓰는 데 문제가 없다.

### `subscribe()` 는 NimBLE 전용이다

`BLERemoteCharacteristic::subscribe()` 가 헤더에 보이지만 **NimBLE 백엔드 선언부**에
있어서 Bluedroid 빌드에서는 존재하지 않는다(컴파일 에러로 확인). Bluedroid 경로는
`registerForNotify()` + CCCD(`0x2902`) 직접 쓰기뿐이고, 쓴 뒤 되읽어 `01 00` 을
확인해야 한다 — 구독이 조용히 실패하면 증상이 "0x01 응답이 안 온다" 하나로만 보인다.

### 적색 평면의 극성이 BW 와 반대다

```
BW  평면: 1 = 흰색,      0 = 검정
RED 평면: 1 = 적색 없음,  0 = 적색      ← 반대
```

적색 평면을 `fillScreen(0)` 으로 채우면 **화면 전체가 빨개진다.**

### `setMTU` 를 부르지 않는다

태그가 `0x01` 응답으로 파트 크기를 직접 알려주므로 우리가 MTU 를 키울 이유가 없다.

### WiFi 와 같이 쓸 때

BLE GATT 전송과 WiFi 프로미스큐어스 스니핑을 동시에 하면 한쪽이 굶는다. 전송 동안만
프로미스큐어스를 끄면 된다(완전히 `esp_wifi_deinit` 할 필요는 없다).

그리고 원시 `esp_ble_gap_*` 콜백을 쓰는 코드가 있으면 **공존하지 못한다** —
`BLEDevice::init()` 이 GAP 콜백을 덮는다. 스캔이 필요하면 `BLEScan` 쪽으로 통일할 것.
무한 스캔이 돌고 있으면 `esl_scan` 전에 `stop()` 하고 **끝나면 콜백과 무한 스캔을
되돌려야 한다** — 안 되돌리면 스캔이 영구히 죽는데 다른 것은 계속 돌아서 원인을
찾기 어렵다.

## 프로토콜

정본은 atc1441 의 리버스엔지니어링(`ATC_GICISKY_ESL`)과 그것을 이어받은
`eigger/hass-gicisky` 다.

```
서비스 0xFEF0   CMD 0xFEF1 (쓰기 + 알림)   IMG 0xFEF2 (쓰기)

1) CMD ← 01                        → 태그가 01 F4 00 (파트메시지 0x00F4=244) 로 답한다
2) CMD ← 02 [총길이 LE32] 00 00 00
3) CMD ← 03                        → 시작
4) IMG ← [파트번호 LE32][데이터 240B]
5) 태그가 05 [상태] [다음파트 LE32] 로 다음 것을 요구한다. 상태 08 이면 완료.
```

픽셀은 **열 우선**이다. 열 하나가 16바이트(128비트), 296열 → 평면당 4736바이트.
`MIRROR_X` 적용.

### 광고에 실린 정보 (연결 불필요)

제조사 데이터, 회사 ID **`0x5053`**, 5바이트:

```
device_id = ((d[4] << 8) | d[0]) & 0x3FFF     모델
battery   = d[1] / 10                          볼트
firmware  = (d[2] << 8) | d[3]
```

실측 예: `33 1D 81 01 40` → id `0x0033`, 2.9V, fw `0x8101`

### 모델 표 (`esl_bwr.cpp` 의 `MODELS[]`)

| id | 모델 | 크기 | 적색 |
|---|---|---|---|
| 0x00A0 | TFT 2.1" BW | 250×132 | — |
| 0x000B | EPD 2.1" BWR | 212×104 | O |
| 0x010B | EPD 2.1" BWR | 250×128 | O |
| 0x0028 | EPD 2.9" BW | 296×128 | — |
| 0x0033 | EPD 2.9" BWR | 296×128 | O |
| 0x002E | EPD 2.9" BWRY | 296×128 | 4색 |
| 0x022B | EPD 3.7" BWR | 240×416 | O (압축) |
| 0x004B | EPD 4.2" BWR | 400×300 | O |
| 0x004E | EPD 4.2" BWRY | 400×300 | 4색 |
| 0x012B | EPD 7.5" BWR | 800×480 | O (압축2) |
| 0x008B | EPD 10.2" BWR | 960×640 | O (압축2) |

같은 2.9인치가 다섯 변종이다. **모델을 모르면 적색 평면 유무도 페이로드 길이도
알 수 없다.**

## 아직 지원하지 않는 것

- **압축 포맷.** 3.7"/7.5"/10.2" 는 줄 단위 청크(`0x75` 헤더) 또는 2비트 패킹을
  쓴다. 표에 플래그만 있고 인코더가 없으므로 그 모델을 물리면 화면이 깨진다.
- **BWRY(4색).** 렌더러가 두 평면만 만든다.
- **296×128 이외 크기.** `ESL_W/ESL_H` 가 고정이고 회전·좌우반전을 표에서 안 읽는다.
  다른 크기를 쓰려면 `esl_pack_planes` 를 표 기반으로 바꿔야 한다.

## 화면을 설계할 때 (이게 제일 많이 틀린다)

전자종이를 LCD 처럼 쓰지 말 것. 성질이 다르다.

| 성질 | 그래서 |
|---|---|
| 이미지 유지에 전력 0 | 화면의 일은 "지금" 이 아니라 **간직할 것을 붙들고 있기** |
| 갱신이 비싸고 느리고(3.5초) 눈에 띈다 | 모든 갱신은 **자격을 얻어야** 한다 |
| 역광 없이 종이처럼 읽힌다 | 지켜보는 매체가 아니라 **흘깃 보는** 매체 |
| 보드가 죽어도 화면이 남는다 | 시각이 없으면 **멈춘 화면이 살아 있는 척 거짓말한다** |

그래서:

1. **실시간 그래프를 넣지 말 것.** 3.5초 걸리는 화면에 초 단위 값은 의미가 없다.
   그래프를 넣을 거면 **긴 것** — 6시간, 7일. 그건 자꾸 고치는 화면으로는 못 보여준다.
2. **계기판이 아니라 기록.** "지금 23도" 보다 "마지막 사건 14:32, 오늘 23건" 이
   종이에 맞는다.
3. **모든 화면에 "언제 기준" 을 박을 것.** 이게 가장 중요하다. 보드가 죽어도 화면이
   남으므로, 시각 없는 화면은 멈춰 있어도 살아 있는 것처럼 보인다.
4. **적색은 "안 봐도 알아야 하는 이진 상태" 에만.** 숫자·그래프·라벨은 가까이서
   읽으니 검정이 더 선명하다. 그리고 검증되지 않은 알람에 적색을 걸면 노이즈에도
   빨개지고, 그러면 적색이 아무 의미가 없어진다.
