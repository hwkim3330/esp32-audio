# BT 오디오 — 죽은 아날로그 경로를 블루투스로 우회한다

이 보드의 I2S/AC101 경로는 실기에서 안 살아났다(`firmware/loopback_test/README.md`).
그런데 **A2DP 는 그 경로를 지나가지 않는다** — 앱이 PCM 을 만들어 블루투스로 바로 보낸다.
공장 펌웨어가 A2DP 싱크로 동작했으니 BT 자체는 확실히 살아 있었다.

## 실기 결과: BT 는 정상, 오디오 기기가 보인다

```
[bt] 컨트롤러 상태 0 → btStart()
[bt] btStart() 성공, 상태 2 (ENABLED)
[bt] bluedroid_init = ESP_OK
[bt] bluedroid_enable = ESP_OK
[bt] MAC 4c:11:ae:f5:a5:1a
[a2dp] 소스 모드 준비

[1] 주변 BT 기기 탐색 (12초)
  b8:b4:09:aa:a1:2f  -60dBm  오디오/비디오
  e0:9d:13:a8:eb:f7  -68dBm  오디오/비디오
  7c:0a:3f:7a:c0:51  -64dBm  오디오/비디오
  기기 80개, 그중 오디오 76개

[2] A2DP 연결 시도: (이름 없음)
  10초 내 연결 안 됨
```

**연결이 안 된 이유는 명확하다.** 처음 보인 오디오 기기를 골랐는데 그건 주변의 남의
기기이고, 페어링 모드가 아니면 연결을 받지 않는다. **이어폰을 페어링 모드로 두고
다시 굽거나 리셋하면 그것이 목표가 된다.**

## 두 가지 결함을 기록해 둔다

**1. 중복 집계.** "기기 80개" 는 리포트 건수다. 같은 MAC 이 여러 번 리포트되므로
실제 고유 기기는 3~5개다. 고유 MAC 으로 묶어야 맞다.

**2. 이름이 안 온다.** 대부분 `(이름 없음)` 인데, 일반 조회(inquiry)만으로는 이름이
안 오는 기기가 많다. `esp_bt_gap_read_remote_name()` 을 따로 불러야 한다.

## 해법: 컨트롤러를 직접 올리지 말 것

이게 이 스케치에서 가장 오래 막힌 부분이다. `esp_bt_controller_init()` 을 직접 부르면
**상태가 IDLE(0) 로 읽히는데도 `ESP_ERR_INVALID_STATE`(0x103)** 가 돌아온다.
세 가지를 시도해도 같았다:

- `bcfg.mode = ESP_BT_MODE_CLASSIC_BT` 로 모드 지정 → 실패
- `esp_bt_controller_mem_release(ESP_BT_MODE_BLE)` 제거 → 실패
- 기본 설정 그대로 → 실패

**Arduino 의 `btStart()` 를 쓰면 즉시 통과한다.** 코어가 컨트롤러 설정을 자기 방식으로
관리하므로 그 진입점을 써야 한다. 상태가 IDLE 로 보이는 것에 속으면 안 된다.

## 이게 열어주는 것

| | 상태 |
|---|---|
| **오디오 출력** (A2DP 소스) | 배관 검증됨. 이어폰 페어링만 남음 |
| **오디오 입력** (HFP Audio Gateway) | 미구현. `esp_hf_ag_api.h` 가 있고, 이어폰이 헤드셋으로 붙으면 그 마이크가 입력이 된다. mSBC 광대역이면 **16kHz 모노 — 음성 모델이 쓰는 그 샘플레이트** |
| 지연 | A2DP 는 100~200ms. 알림·응답은 충분, 건반 연주는 불가 |

출력이 살아나면 되살아나는 것: 부팅 확인음(화면 없는 문제의 해법), 번역 무전기 응답,
상태 알림. 입력까지 살아나면 `cabin_node` 의 음성 인식이 통째로 돈다.
