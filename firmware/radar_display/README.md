# 2.4GHz 레이더 + 전자종이 화면

`multiband_sense`(센싱)와 `esl_display`(화면)를 합친 것. 이 보드에서 도는 최종 형태다.
PC 없이 동작하고, 결과를 벽에 붙은 전자종이 4대에 스스로 그린다.

## 무엇이 실기로 확인됐고 무엇이 아닌가

| | 상태 |
|---|---|
| WiFi CSI 수신 (ch1/6/11) | **확인.** 서브캐리어 64개, 10~20Hz |
| 온보드 추론 | **확인.** 314~334ms, 라이브 CSI 로 창→인코더→매칭 |
| 채널 분류 정확도 | **확인.** 45~53% (무작위 33%) — 파이프라인이 맞다는 증거 |
| BLE 광고 스캔 | **확인.** 기기 47대, 누적 3만 광고 |
| 앵커 링크 (고정 위치) | **확인.** 4대, 정지 시 편차 1.4~5.5dB |
| 전자종이 4대 갱신 | **확인.** 20~40파트, 3.0~5.5초 |
| 버튼 6개 | **확인.** 핀 매핑 실기 확정 |
| **사람 감지** | **미확인.** 전부 빈 방 기준선이다 |
| 마이크 | **죽음.** I2S 가 정확히 0 |

## 사람 감지가 왜 아직 미확인인가

지금까지의 모든 숫자는 빈 방에서 나왔다. "사람이 지나가면 점수가 오른다" 는 것은
사람이 지나가야 확인된다. 그래서 보드가 스스로 검증하게 만들었다:

**K1 을 누르고 지나가면** 그 구간이 "마크" 로 표시된다. 보드가 마크 구간과 비마크
구간의 점수 분포를 따로 누적해서 평균·적중률·**Cohen's d** 를 낸다. d 가 0.8 을
넘으면 "센서가 사람을 본다" 를 숫자로 말할 수 있다. 사람이 필요하지만 필요한 것은
**버튼 한 번**이고, 판정은 보드가 한다.

그리고 **적색은 그 검증을 통과해야 켜진다.** 전자종이에서 적색의 유일한 값은 "읽지
않아도 눈에 들어온다" 인데, 검증 안 된 알람에 적색을 걸면 노이즈에도 빨개지고 적색이
의미를 잃는다. d ≥ 0.8 이 될 때까지는 전부 흑백이다.

## 앵커 링크 — 익명 47대보다 고정 4대가 낫다

처음의 BLE 점수는 주변 기기 47대의 RSSI 변동에서 나왔다. 문제는 그 대부분이
**휴대폰**이라는 것이다.

- 휴대폰은 **스스로 움직인다** → 신호가 흔들려도 사람이 지나가서인지 그 폰이
  주머니에서 움직여서인지 구분할 수 없다.
- **MAC 을 랜덤화한다** → 같은 기기를 계속 추적할 수 없다(실측 96대 중 82대가
  이름 없는 랜덤 MAC).

전자종이 태그는 반대다. **벽에 붙어 있고, 움직이지 않고, MAC 을 안 바꾼다.** 그래서
태그 하나가 보드↔태그 **경로 하나**를 대표하고, 그 경로의 RSSI 가 흔들리면 그 선분을
가로지른 것이 있다는 뜻이다 — 바이스태틱 감지의 정의 그대로다. 네 대면 네 경로이므로
어느 쪽이 흔들리는지가 방향 정보가 된다.

정지 상태 잡음(실측):

```
75:78  -50.4 dBm  편차 2.29 dB   표본 108
73:06  -52.1 dBm  편차 4.21 dB   표본 109
95:81  -55.2 dBm  편차 2.69 dB   표본 102
73:04  -59.0 dBm  편차 5.51 dB   표본  52   ← 유독 시끄럽고 표본도 절반
```

이 편차가 곧 감지 문턱이다. 사람이 경로를 막을 때 2σ = 4.6~11dB 넘게 움직여야 잡힌다.

**앵커에서는 최댓값이 맞다.** 넷뿐이라 다중비교 걱정이 작고, 각 경로가 물리적으로
의미가 있어 한 경로만 막혀도 사람이 있는 것이다. 익명 기기 쪽은 개수가 많아 최댓값이
오염되므로 "2σ 넘는 비율" 을 쓴다 — 같은 신호를 두 방식으로 다루는 이유가 이것이다.

## 실기에서 잡은 조용한 버그들

### 서브캐리어 개수는 고정이 아니다

`sc64` 로 알고 있었는데 어느 순간 `sc128` 이 됐다. AP 가 HT40 으로 올라간 것이다.
더 파보니 **64(20MHz) / 128(HT40) / 192(HT40+STBC)** 가 섞여 들어온다.

이걸 그냥 받으면 조용히 망가진다. 모델은 64개로 학습됐고, 링의 한 행은 `2*n_sc`
바이트로 고정 배치되므로 프레임마다 개수가 다르면 행이 어긋난다. 증상은 "인식률이
왜 이러지" 로만 보이고 원인이 감춰진다. 그래서 **기대하는 개수만 받고 나머지는 세어서
알린다** — 조용히 버리면 "왜 프레임이 안 들어오나" 를 또 오해한다.

### 키 매핑이 두 칸 밀려 있었다

"3번 키만 반응한다" 는 증상이었다. 핀 변화 감시기(후보 12핀을 50Hz 로 훑어 바뀐 핀
번호를 찍는다)로 버튼을 하나씩 눌러보니 **여섯 개 다 작동했다.**

```
KEY1=GPIO36  KEY2=GPIO13  KEY3=GPIO19  KEY4=GPIO23  KEY5=GPIO18  KEY6=GPIO5
```

내 배열은 `{19, 23, 18, 5, 36, 13}` 로 두 칸 밀려 있었다. 물리 KEY3(GPIO19)이
코드에서 K1 = 마크 토글이었고, **마크 토글만 LED 라는 눈에 보이는 효과가 있었다.**
나머지 다섯 개는 잘 작동하면서 시리얼에만 찍혔다.

교훈: 화면도 LED 응답도 없으면 **"안 되는 것" 과 "되는데 안 보이는 것" 이 구별되지
않는다.** 그래서 모든 키에 LED 응답을 붙였다 — 누른 키 번호만큼 깜빡인다.

### 근거 없는 자동 비활성이 멀쩡한 키를 죽였다

부팅 시 LOW 로 읽히는 키를 배선 의심으로 끄고 있었다. 그게 GPIO13(KEY2)을 잡았는데
감시기로 보니 정상이었다. LOW 로 읽힌 이유는 **순서**였다 — 키 스캔이 LED 핀 설정보다
먼저 돌아서 GPIO22 가 떠 있을 때 읽었고, GPIO13 은 GPIO22 상태에 끌린다.
LED 를 먼저 설정한 뒤 읽고, 값이 이상해도 끄지 않고 알리기만 한다.

### 적색을 안 보내는 것은 적색을 끄는 것이 아니다

**전자종이는 잔류형이다.** 흑백 평면만 보내면 태그의 적색 레이어는 지워지지 않고
이전 내용이 그대로 남는다. 흑백 전용으로 바꾼 뒤에도 화면이 계속 빨갰던 이유다.
적색을 없애려면 적색 평면을 **흰색으로 채워서 함께 보내야** 한다. 대가는 페이로드
두 배인데, 속도 차이가 없다는 것은 이미 쟀다(BWR 4074ms 대 흑백만 4327ms — 병목이
바이트가 아니라 연결 수립과 태그의 리프레시다).

### 원시 BLE 콜백과 GATT 클라이언트는 공존하지 못한다

센싱은 `esp_ble_gap_*` 콜백으로 광고를 셌는데 `BLEDevice::init()` 이 그 콜백을 덮는다.
센싱도 `BLEScan` 콜백으로 옮겨 스택을 하나로 통일했다. 화면 갱신 때는 스캔 소유권을
`stop()` 으로 넘겨받고 끝나면 **콜백과 무한 스캔을 되돌린다** — 안 되돌리면 BLE 점수가
영원히 0 이 되는데 WiFi 는 계속 돌아서 "BLE 만 이상하다" 로 보인다.

### 추론이 절반 넘게 헛돌았다

추론 175회에 프레임 부족 건너뜀 181회. 채널 체류 6초 중 앞 2초는 링에 그 채널
프레임이 없어 창을 못 만들었다. 체류를 10초로, 전환 후 2.2초는 시도조차 안 하게
바꿔서 96회에 71회가 됐다. 대가는 한 채널을 다시 보기까지 18초 → 30초인데, 추세
그래프가 1초마다 찍히므로 문제없다.

## 영속 저장

재부팅하면 전부 사라지는 것이 가장 큰 구멍이었다. 벽에 붙여둘 센서인데 며칠에 걸쳐
증거를 모을 수 없으면 K1 검증이 무의미하다 — 한 번 지나가는 것으로는 표본이 안 모인다.

NVS 에 남기는 것은 **누적된 증거와 사람이 정한 값**뿐이다: 마크/비마크 통계, 채널
혼동행렬, 임계값, 부팅 횟수. 5분 주기 + 사람이 값을 바꿀 때 즉시.

**기준선(base_mu/sd)은 일부러 안 남긴다.** 전파 환경은 시간이 지나면 바뀌므로 묵은
기준선을 되살리면 부팅 직후 유령 감지가 난다. 다시 배우는 데 40프레임이면 된다.

## 버튼

| 키 | GPIO | 짧게 | 길게(2초) |
|----|------|------|-----------|
| K1 | 36 | **마크 토글** (검증의 핵심) | 기준선 재학습 |
| K2 | 13 | 임계값 −0.5 | |
| K3 | 19 | 임계값 +0.5 | |
| K4 | 23 | 화면 즉시 갱신 | 채널 고정/순환 |
| K5 | 18 | 페이지 회전 | 통계 출력 |
| K6 | 5 | 통계 출력 | |

누르면 **키 번호만큼 LED 가 깜빡인다.** 화면 없이 먹었는지 확인하는 유일한 방법이다.

## 화면 4장

RSSI 순으로 배정된다(가장 가까운 태그가 0번). K5 로 회전시킬 수 있어 태그를 벽에
붙인 채로 배치를 실험할 수 있다.

0. **추세 그래프** — 대역 점수 72초, 임계선(점선), 앵커 4경로 막대, 부팅/가동시간
1. **모델** — 추론 지연, 채널 혼동행렬, 창 프레임 수·건너뜀
2. **전파 이웃** — 채널별 패킷, AP MAC, BLE 기기·광고, 프로빙 상태
3. **태그 자신** — 모델 id, 펌웨어, 전압, 업로드 성공/실패

## 남은 것

- **사람 감지 검증.** K1 을 누르고 지나가야 한다.
- **CSI 위치 라벨.** 지금 모델은 "채널 분류기" 다 — 위치 라벨이 없어 그걸로 학습했다.
- **능동 프로빙이 안 통한다.** 브로드캐스트 프로브 1.13배, 널+ACK 1.22배. 조사에서
  본 10~20배는 이 보드에서 재현되지 않았다.
- **마이크.** 남은 단일 용의자는 가운데 DIP 스위치(물리).
- `73:04` 태그가 유독 시끄럽고(편차 5.5dB) 적색도 안 나온다. 개체 문제로 보인다.
