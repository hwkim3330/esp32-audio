# 캐빈 노드 펌웨어 — 번역 무전기

보드 하나로 완결된다. PC 없음, 클라우드 없음, SD 없음.

**누르고 말한다 → 온디바이스 인코더가 한국어 문장을 알아맞힌다 → 그 뜻의 다른 언어
음성이 스피커로 나온다.** 40문장 × 4언어(en/ja/es/vi) 가 전부 플래시에 있어서
태블릿이 아예 필요 없다. 붙이면 화면과 문장 추가가 생긴다.

## 빌드

```bash
arduino-cli lib install --git-url https://github.com/Yveaux/AC101   # GPL-3.0 주의
arduino-cli compile --fqbn \
  'esp32:esp32:esp32:PSRAM=enabled,FlashSize=4M,PartitionScheme=custom,CPUFreq=240' \
  firmware/cabin_node
```

`PartitionScheme=custom` 이 중요하다. 스케치 폴더의 `partitions.csv` 가 앱에 3.9MB 를
준다 — OTA 도 SPIFFS 도 안 쓰므로 `huge_app`(3MB) 이 남기는 1MB 를 앱에 돌린다.
그 1MB 가 "문장 30개" 와 "문장 40개 전부" 를 가른다.

빌드 결과 (실측):

```
Sketch uses 3641447 bytes of program storage space.
Global variables use 47720 bytes (14%) of dynamic memory.
```

앱 파티션 0x3F0000 = 4,128,768 바이트 중 3,641,447 사용 — 88%, 여유 476KB.
(arduino-cli 가 표시하는 "Maximum is 16777216" 은 커스텀 파티션에서 잘못 나오는
값이니 무시할 것. 실제 상한은 partitions.csv 의 app0 크기다.)

## 자원을 어디에 쓰는가

"기능 다 쓰기" 가 요구사항이었고, 실제로 다 쓴다.

| 자원 | 있는 것 | 쓰는 것 | 무엇에 |
| --- | --- | --- | --- |
| **플래시** | 4MB (앱 파티션 3.9MB) | **88%** | 인코더 268KB + 프로토타입 46KB + 구문 음성 2238KB + 코드 |
| **PSRAM** | 4MB | 약 2.1MB | 스테레오 링 640KB + 추론 964KB + 발화 288KB + 재생 224KB |
| **내부 DRAM** | 320KB | 14% | 나머지는 전부 PSRAM 으로 밀어냈다 |
| **코어 0** | 240MHz | 상시 | I2S 캡처 + 링버퍼 + VAD |
| **코어 1** | 240MHz | 발화 시 | 로그멜 + 추론 + 매칭 + 재생 |
| **마이크** | **2개** | 둘 다 | 방향 추정(좌/중/우) + 모노 합성 |
| **스피커** | DAC + 앰프 | 씀 | ADPCM 디코딩 + 실시간 피치/톤 컬러링 |
| **터치키** | 6개 | 3개 | KEY1 = PTT, KEY2 = 언어 전환, KEY6 = 뮤트 |
| **WiFi** | 있음 | 옵션 | 태블릿 링크 (없어도 단독 동작) |

PSRAM 이 왜 필요한지는 링크 에러가 증명했다. 재생·발화 버퍼 416KB 를 내부 DRAM 에
두면 **DRAM 이 339KB 초과**하며 링크가 깨진다. 그 버퍼를 PSRAM 으로 옮겨서 통과했다.

## 왜 ADPCM 인가

용량이 전부다. 16kHz 16bit 모노는 32KB/s 라 2.2MB 에 70초밖에 안 들어가지만, 4비트
IMA-ADPCM 은 8KB/s 라 280초가 들어간다. **4배 차이가 "언어 1개" 와 "언어 4개" 를
가른다.** ADPCM 은 곱셈이 없는 정수 코덱이라 디코딩 비용도 사실상 0 이다.

인코더(파이썬)와 디코더(C)가 같은 테이블을 쓰는지 검증했다 — 왕복 SNR 31.6dB 가
양쪽에서 동일하게 나온다. 여기가 어긋나면 보드에서 잡음만 난다.

## 부팅 시 스스로 확인하는 것

임베디드에서 "돌긴 도는데 값이 미묘하게 다름" 은 데모 중에 인식률 문제로 위장해서
나타난다. 그래서 두 가지를 부팅 때 검증하고, 실패하면 진행하지 않는다.

1. **AC101 I2C 프로브** — `board_pins.h` 의 핀 가정이 맞는지 실측한다. 코덱이 응답하지
   않으면 무엇을 확인해야 하는지 출력하고 멈춘다. 잘못된 핀으로 I2S 를 켜지 않는다.
2. **추론 자기검증** — `selftest.h` 의 알려진 멜 입력으로 알려진 임베딩이 나오는지 본다
   (허용 2e-3). PC 에서 numpy 참조와 코사인 0.9999999 로 일치함을 이미 확인했다.

직접 고치지 말 것.

## 실기 측정 결과 (2026-08-05, 실제 보드)

굽고 나서 나온 값이다. 부팅 로그 그대로:

```
PSRAM 4093 KB 사용 가능
[probe] I2C SDA=33 SCL=32 addr=0x1A → 응답 있음
AC101 초기화 완료
PSRAM 배치: 링 625KB, 추론 964KB, 발화 281KB, 재생 218KB, 남음 1944KB
자기검증 1회: 통과 (오차 1.27e-07, 2456ms)
자기검증 2회: 통과 (오차 1.27e-07, 2454ms)
자기검증 3회: 통과 (오차 1.27e-07, 2455ms)
로그멜(1초): 85ms
```

**좋은 소식 둘.** `board_pins.h` 의 핀 가정이 맞았다 — 소프트웨어만으로 식별한 SDA=33 /
SCL=32 에서 AC101 이 실제로 응답한다. 그리고 보드에서 도는 추론이 PC 의 numpy 참조와
**오차 1.27e-07** 로 일치한다. 3단계 수치 검증이 실기까지 이어졌다.

**나쁜 소식 하나 — 추론이 2455ms 다.** 200~400ms 로 추정했으니 6배 이상 틀렸고,
3회 모두 같은 값이니 캐시 워밍이 아니라 정상 속도다.

### 왜 느린가 — 그리고 왜 내 int8 판단이 틀렸는가

8.14M MAC / 2455ms = **3.3 MMAC/s**. 240MHz FPU 에서 MAC 당 73 사이클이면 연산이 아니라
메모리 대기다. 가중치는 플래시, 활성값은 PSRAM 인데 둘 다 같은 SPI 버스를 캐시로
통과한다. 게다가 pointwise conv 가 출력 채널마다 입력 평면을 다시 읽어서 캐시를 갈아낸다.

이 프로젝트 초기에 "ESP32 는 SIMD 가 없으니 int8 로 내려도 속도 이득이 없다" 고 판단해
float32 를 골랐다. **그 판단은 틀렸다.** 병목이 연산이 아니라 대역폭이므로 int8 은
트래픽을 4배 줄여서 실제로 크게 이긴다. 참고로 로그멜은 1초 오디오에 85ms 로 충분히
빠르다 — 순차 접근이라 같은 병목에 걸리지 않는다.

### 고치는 순서

1. **stem 이후 활성값을 내부 DRAM 으로** — 재학습 없음. stem 출력만 246KB 이고 그 뒤는
   최대 123KB 라 두 버퍼가 내부에 들어간다. MAC 대부분이 stem 이후에 있다. 약 600ms 예상.
2. **int8 양자화** — 트래픽 4배 절감. 1번과 합쳐 150~200ms 예상.
3. **conv 루프 타일링** — 입력 평면이 캐시에 머물도록 순서를 바꾼다.
4. 입력 프레임 수 축소 (192 → 128) — 정확도와 교환.

## 아직 안 한 것
- **실제 마이크 인식률 미검증.** 모델 정확도(학습에서 제외한 문장 0.963, 인텐트
  0.948)는 전부 합성 음성 기준이다. OOD 오수락 8.1%(교차검증 10.1%)도 마찬가지다.
- **태블릿 앱 없음.** WiFi 링크는 TCP 로 열려 있고 JSON 한 줄을 보낸다. 반대편이 없다.
- **PSRAM 구문 캐시 미구현.** `find_entry()` 가 플래시만 본다. 지금은 40문장 전부가
  플래시에 있어서 필요가 없지만, 문장을 더 늘리면 이 경로가 필요하다 (PSRAM 1944KB 여유).
- **A2DP · ULP · 배터리 모니터 미사용.** 지금 문제를 풀지 않아서 뺐다.

## 라이선스 주의

AC101 드라이버(`Yveaux/AC101`)가 **GPL-3.0** 이다. 링크하면 이 펌웨어도 GPL-3 이 되고
소스 공개 의무가 생긴다. 레포가 공개라 실질 문제는 없을 수 있지만, 과제 산출물이면
확인이 필요하다. 대안은 ESP-ADF(Apache-2.0) 기반의 `pschatzmann/arduino-audiokit` 이고,
코덱 호출은 `setup()` 안 몇 줄에 모여 있어 교체가 작다.
