# WiFi CSI 감지 — 오디오가 죽은 보드로 하는 온디바이스 감지

이 보드의 마이크·스피커는 실기에서 안 살아났다(`firmware/loopback_test/README.md`).
그런데 WiFi 는 멀쩡하고, ESP32 는 **CSI(Channel State Information)** 를 뽑을 수 있다.
CSI 는 전파가 사람 몸에 반사·회절되며 변하는 양이라, 이걸로 재실·움직임을 읽는다.

**카메라도 마이크도 필요 없다. 추가 부품 0. AP 접속도 자격증명도 없다.**

프로미스큐어스 모드로 주변 AP 의 비콘(약 100ms 주기)을 받으면 CSI 가 생성되므로
어디서나 그냥 동작한다.

## 실기 결과 (2026-08-05)

```
=== WiFi CSI 감지 ===
PSRAM 시계열 버퍼 0.29 MB (600 프레임 × 128 서브캐리어)
CSI 활성화 완료

[1] 붐비는 채널 찾기
  채널  1 → 31 프레임/1.2초
  채널  6 → 59 프레임/1.2초     ← 선택
  채널 11 →  4 프레임/1.2초

[2] 기준선 학습 (120 프레임)
  기준선 완료: 서브캐리어 64개, 평균진폭 15.8, 평균표준편차 5.61

[3] 감지
sc 64  268.0 Hz  dev   0.00  flux   1.59  motion 0
sc 64  210.0 Hz  dev   0.63  flux   5.63  motion 0
sc 64   14.0 Hz  dev   1.14  flux  11.61  motion 0
```

빌드 917KB (29%), DRAM 13%.

`motion` 이 0 인 것은 정상이다 — 아무도 지나가지 않았다. `dev` 가 빈 방에서 0.5~1.4
사이로 움직이는 것이 지표가 살아있다는 증거고, 임계값 3.0 은 그 위에 잡아 뒀다.

**아직 실제 움직임으로 검증하지 않았다.** `motion` 은 누적 카운터이므로, 보드 앞을
지나간 뒤 나중에 시리얼을 읽으면 흔적이 남는다.

## 왜 PSRAM 이 여기서 제 몫을 하는가

CSI 를 시계열로 쌓아야 "정적 기준선" 과 "변화" 를 구분할 수 있다. 내부 DRAM 으로는
몇 초가 한계인데 PSRAM 4MB 면 수 분을 담는다. 현재 600프레임 × 128서브캐리어 = 0.29MB
를 쓰고 있고, 훨씬 늘릴 여유가 있다.

중요한 점: 이 접근은 **순차 접근**이라 PSRAM 이 느리지 않다. 캐빈 노드에서 추론이
2455ms 나온 원인은 랜덤 접근이었다(`firmware/cabin_node/README.md`).

## 두 지표

| 지표 | 정의 | 성질 |
| --- | --- | --- |
| `flux` | 직전 프레임 대비 진폭 변화량 평균 | 움직임에 즉각 반응, 기준선 불필요 |
| `dev` | 기준선 대비 z-score 평균 | 정적 환경을 학습한 뒤의 이상 정도 |

`flux` 는 기준선 없이도 되므로 트래픽이 적은 곳에서도 쓸 수 있고, `dev` 는 오래
비어 있던 공간에 뭔가 들어온 것을 잡는 데 강하다.

## 다음 — 학습된 모델을 얹을 수 있다

CSI 시계열은 **600프레임 × 64서브캐리어 행렬**이다. 그게 `model/` 의 인코더가 먹는
멜 스펙트로그램(192 × 40)과 **같은 모양**이다. 즉 이미 만들어 둔 파이프라인을 그대로
재사용해 CSI 로 상태를 분류할 수 있다:

- 빈 차 / 사람 있음 / 움직임 / 뒷좌석에 누가 있음

그 파이프라인은 이 보드에서 이미 검증됐다 — 온보드 추론이 PC numpy 참조와
**오차 1.27e-07** 로 일치한다(`firmware/cabin_node/README.md`).

학습 데이터는 Supertonic 합성처럼 공짜로 만들 수 없으므로(전파는 실측이 필요하다)
사람이 여러 상태로 있는 동안 CSI 를 수집해야 한다. 그게 이 방향의 유일한 비용이다.

## 용도

차량 실내 재실 감지(아이 방치 감지)가 실제 자동차 안전 기능이고, **카메라·마이크
없이 된다는 것이 그 용도의 핵심 장점**이다 — 사생활 문제가 구조적으로 없다.
