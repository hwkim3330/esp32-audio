# web_mp3 — 브라우저로 넣고 블루투스로 듣는 MP3 플레이어

이 보드의 3.5mm 잭은 죽어 있다. 그래도 MP3 플레이어는 된다 — 출력을 A2DP 로 뺀다.

```
MP3 파일 (SD 또는 내장 플래시)
   → minimp3 디코드 → 44.1kHz 스테레오 리샘플 → PSRAM 링버퍼 256KB
   → A2DP 소스 데이터 콜백 → SBC 인코딩(BT 컨트롤러) → 이어폰/스피커
조작: 웹 UI(WiFi) + 온보드 버튼 6개
```

## 왜 A2DP 인가 — 잭으로는 못 낸다

`firmware/loopback_test` 에서 확정했다: **I2S 가 정확히 0 을 내보낸다.** DIN 후보 8개,
`ADC_SRC` 9개, `ADC_APC_CTRL` 9개, `ADC_VOL_CTRL` 6개, `MODE_ADC`/`ADC_DAC`, APLL on/off —
전부 무신호. AC101 I2C 는 양방향으로 완벽하다. 남은 단일 용의자는 **가운데 DIP 스위치**
(물리 점퍼)다. 소프트웨어로 넘을 수 있는 벽이 아니다.

A2DP 는 그 경로를 안 지나간다. 앱이 PCM 을 만들어 BT 컨트롤러에 바로 넘긴다.

| --- | --- | --- |

| 부팅 · PSRAM | **됨** — PSRAM 여유 3800KB, 내부 힙 190KB | 부팅 로그 |

| BT 컨트롤러 + A2DP 소스 init | **됨** — MAC `…f5:a5:1a`, 이름 `KETI-MP3` | 부팅 로그 |
| SD → HTTP 다운로드 | **됨 — 약 630 KB/s** | 1.9GB 백업 실측 |

| **MP3 디코드 (44.1k 스테레오)** | **됨** — `src=44100Hz/2ch/128k` | 실기 |
| **리샘플러 + 모노→스테레오 (48k 모노)** | **됨** — `src=48000Hz/1ch/96k` | 실기 |
| **재생 속도** | **정확히 실시간** — 6초에 I2S 266,240프레임 = 44,373fps | 실기 |
| 다음 곡 자동 넘김 | **됨** | 실기 |
| 잭 출력(AC101/I2S) 배관 | **됨** — I2S 가 44.1kHz 로 계속 밀려나간다 | 실기 |
| **잭에서 실제로 소리가 나는가** | **미확인 — 사람 귀가 필요하다** | 웹 UI 테스트음 |
| **이어폰 A2DP 연결·재생** | **미검증** | 페어링 모드로 둔 이어폰이 필요하다 |
| 마이크 녹음 | **불가** — 입력(ADC)이 정확히 0 | 음향 폐루프 자기진단 |

즉 `파일 → 디코드 → 리샘플 → 링버퍼 → I2S → AC101` 까지는 실측으로 다 확인됐다.
남은 미지는 **AC101 뒤 아날로그 한 구간**뿐이다.

`SD_MMC.usedBytes()` 가 찍는 사용량은 **믿지 마라.** 실제 1.9GB 가 든 카드를 65MB 로
보고했다(exFAT). 용량을 알아야 하면 `tools/sd_backup.py --dry-run` 으로 세라.

## SD 카드는 읽기 전용이다 (의도한 설계)

카드에 남의 데이터가 있을 수 있다(실제로 GoPro HERO4 영상 1.9GB 가 들어 있었다).
그래서 이 펌웨어에는 **SD 쓰기 경로가 아예 없다**:

- 업로드는 언제나 내장 플래시(LittleFS)로 간다
- `/api/delete` 는 플래시에 올린 파일만 지운다. SD 파일 이름을 주면 404
- `SD_MMC.begin(..., format_if_empty=false)` — 빈 카드도 포맷하지 않는다
- 재생은 SD 를 읽기만 한다

카드를 통째로 내려받으려면 PC 에서:

```bash
tools/sd_backup.py 192.168.4.1 --dry-run     # 목록·용량만
tools/sd_backup.py 192.168.4.1               # ~/esp32_audio_kit/sd_backup 으로
```

크기가 같은 파일은 건너뛰고, 받다 만 파일은 **바이트 단위로 이어받는다**.

`streamFile` 을 쓰지 않고 Range 를 직접 처리한 이유가 이것이다 — WebServer 의
`streamFile` 은 Range 를 무시하고 늘 전체를 보낸다. 630KB/s 로 1.4GB 파일을 받으면
37분이 걸리는데, 그 사이 한 번 끊기면 처음부터 다시 받아야 했다. 부수 효과로
전송률도 420 → 630KB/s 로 올랐다(4KB 씩 직접 밀어서).

`collectHeaders()` 로 `Range` 를 명시해야 `header("Range")` 가 값을 준다 — 기본으로는
수집되지 않는다.

## 굽기

```bash
arduino-cli compile --fqbn \
  'esp32:esp32:esp32:PSRAM=enabled,FlashSize=4M,PartitionScheme=custom,CPUFreq=240' \
  firmware/web_mp3
arduino-cli upload -p /dev/ttyUSB0 --fqbn \
  'esp32:esp32:esp32:PSRAM=enabled,FlashSize=4M,PartitionScheme=custom,CPUFreq=240' \
  firmware/web_mp3
```

`PartitionScheme=custom` 이 이 폴더의 `partitions.csv` 를 집어간다. arduino-cli 가 찍는
`Maximum is 16777216` 은 커스텀 파티션에서 나오는 헛값이다 — 진짜 한도는 `partitions.csv` 다.

## 쓰는 법

1. 저장한 AP 가 없으면 보드가 **AP 모드**로 뜬다: SSID `esp32-mp3` / 비번 `12345678` →
   `http://192.168.4.1/`
2. 웹 UI 의 WiFi 칸에 집/사무실 AP 를 넣으면 재부팅해서 STA 로 붙는다
   (`http://esp32-mp3.local/` 도 된다)
3. 이어폰을 **페어링 모드**로 두고 `기기 탐색` → 목록에서 고르면 A2DP 로 붙는다.
   한 번 붙은 기기는 NVS 에 저장돼 다음 부팅에 자동 재연결한다
4. MP3 를 끌어다 놓으면 내장 플래시로 올라간다(2MB 남짓 = 128kbps 3분 곡 한 곡쯤).
   여러 곡은 SD 에 넣는 편이 낫다 — 루트와 한 단계 아래 폴더에서 `.mp3` 를 최대 200개 모은다

## 버튼 6개

실기로 확정한 매핑(`KEY1=36 KEY2=13 KEY3=19 KEY4=23 KEY5=18 KEY6=5`)을 그대로 쓴다.

| 키 | 짧게 | 길게(1.2초) |
| --- | --- | --- |
| KEY1 | 재생/일시정지 | 정지 |
| KEY2 | 다음 곡 | |
| KEY3 | 이전 곡 | |
| KEY4 | 음량 +5 | |
| KEY5 | 음량 −5 | |
| KEY6 | 마지막 기기로 재연결 | BT 기기 탐색 |

LED(GPIO22): 켜짐=스트리밍, 느린 깜빡임=연결만, 빠른 깜빡임=미연결.

## 녹음 (온보드 마이크 2개 → SD)

44.1kHz 16비트 스테레오 WAV 로 SD 의 `/REC` 에 쓴다(초당 176KB). 웹 UI 의 버튼 하나,
또는 `POST /api/rec?on=1|0`. 받은 파일은 `/sd/REC/rec_001.wav` 로 내려받는다
(Range 를 지원하므로 이어받기도 된다).

실기 검증: 7.94초 녹음 → `pcm_s16le 44100Hz 2ch`, 길이가 보고값과 일치,
**클리핑 없음**(피크 2099/32767), 조용한 방에서 RMS L 543 / R 272.

**마이크 게인을 조심하라.** 처음에 `ADC_VOL_CTRL=0xc0c0` 을 썼다가 최대값이 32767 에
붙어 클리핑했다(RMS 10152). 그 값은 `loopback_test` 가 **자기 톤 검파용**으로 고른
것이고 녹음에는 과하다. 기본은 `0xa0a0`(begin() 기본값)이고, 프리셋 4단계를
`POST /api/micgain?v=0..3` 으로 고른다. 상태의 `recpeak` 가 32767 이면 낮춰라.

녹음을 시작하면 재생이 멈춘다 — 마이크가 보드 위에 있어서 잭/스피커로 나가는 소리를
그대로 다시 듣는다.

**입력은 온보드 마이크 2개뿐이다.** 4핀(TRRS) 이어폰의 마이크는 이 보드에 배선돼
있지 않다 — `firmware/mic_scan` 으로 확정했다(아래 참고). 그러니 그 이어폰의 인라인
버튼도 쓸 수 없다.

## 청음 시험을 내 코드가 스스로 망치고 있었다

`loopback_test/board_pins.h` 는 **GPIO22 를 `PA_ENABLE`(파워앰프 인에이블, 가정)** 으로
적어 두었다. 그런데 이 저장소의 스케치들은(내가 만든 것 포함) **같은 핀을 상태 LED 로
깜빡여 왔다.** 22 가 정말 앰프 인에이블이면 그건 청음 시험 내내 앰프를 초당 2~4회
켜고 끄는 짓이고, 그 상태로 "안 들린다" 는 판정을 내리면 무효다.

고쳤다: **GPIO22 와 GPIO21 을 둘 다 계속 HIGH 로 못박고, 깜빡이지 않는다**(리비전에
따라 21 을 쓴다). 상태 표시는 웹 UI 와 시리얼로만 한다.

## DIP 스위치 가설은 근거가 약하다

`docs/HARDWARE.md` 에 따르면 가운데 DIP 는 **SD/JTAG/키 GPIO 를 갈라주는 점퍼**다 —
코덱 아날로그 경로와 상관이 없다. 그리고 **SD 카드가 1비트로 정상 마운트된다**(16GB
인식, 1.9GB 를 실제로 읽어냈다) = 이미 SD 위치라는 뜻이다. 그러니 "오디오가 죽은 건
DIP 때문" 은 지지 근거가 없다. 토글하면 SD 가 깨질 뿐이다.

## 코덱 레지스터는 이미 출력이 켜진 상태다

실측 판독 vs 라이브러리 `SetMode(MODE_DAC)` 가 쓰는 값:

| 레지스터 | 실측 | 라이브러리 의도 |
| --- | --- | --- |
| `OMIXER_DACA_CTRL` 0x53 | `0xFF80` | `0xff80` — 일치 |
| `HPOUT_CTRL` 0x56 | `0xFB20` | `0xfbc0` + 볼륨비트 — 일치 |
| `SPKOUT_CTRL` 0x58 | `0xEAB9` | `0xeabd` + 볼륨비트 — 일치 |
| **`OMIXER_SR` 0x54** | **`0x0081` (리셋 기본값)** | **라이브러리가 한 번도 안 쓴다** |

즉 소프트웨어로 남은 단일 미시도 후보는 **`OMIXER_SR`** 하나다(출력 믹서에 무엇을
넣을지 고르는 레지스터). 다만 **이걸 스윕해도 들어줄 사람이 없으면 판정이 안 된다** —
지금 병목은 가설이 아니라 계측이다. `--dry` 로 확인할 수 있는 종류가 아니다.

객관 판정 방법 두 가지:
1. 사람이 한 번 듣는다 (웹 UI 의 잭 테스트음)
2. **3.5mm 수-수 케이블로 보드 잭 → PC 라인인**. 그러면 PC 가 디지타이즈하니 사람
   없이 판정되고, 주파수·좌우·왜곡까지 잰다. (이 PC 캡처는 지금 **정확히 0** 을
   녹음한다 — 아무것도 안 꽂혀 있다는 뜻이라, 케이블이 있어야 이 길이 열린다)

## 두 번 죽고 알아낸 것 — 내부 DRAM 이 이 보드의 진짜 천장이다

**1. minimp3 의 프레임 스크래치가 15KB 다. 그게 스택에 있었다.**

원본 `mp3dec_decode_frame()` 은 `mp3dec_scratch_t` 를 스택에 잡는다. 6KB 스택 태스크로
부르면 `Guru Meditation Error: Stack canary watchpoint triggered (dec)` 로 즉사한다.
**스택을 키우는 건 답이 아니었다** — 초기화가 끝나면 내부 DRAM 이 27KB 밖에 안 남는데
24KB 스택을 달라는 얘기가 되기 때문이다.

그래서 벤더링한 `minimp3.h` 를 개조해 스크래치를 **PSRAM** 으로 뺐다(CC0 이라 자유롭다):

```c
mp3dec_set_scratch(ps_malloc(mp3dec_scratch_size()));   // setup() 에서 한 번
```

디코더를 부르는 태스크가 하나라는 전제다. 개조 지점은 `minimp3.h` 안에 주석으로 남겼다.

**2. BLE 몫의 컨트롤러 메모리를 반납해야 한다.**

이 펌웨어는 클래식 BT(A2DP)만 쓰는데, 반납하지 않으면 내부 DRAM 을 30~40KB 쥐고 앉아
있다. `btStart()` **보다 먼저** 불러야 먹는다:

```c
esp_bt_controller_mem_release(ESP_BT_MODE_BLE);
```

실측: 초기화 후 남는 힙이 **14KB → 27KB**. 재생 중에도 15KB 로 안정된다.
이 두 개를 고치기 전에는 재생 명령을 넣는 순간 죽었다.

## 설계에서 조심한 것들

- **`btStart()` 를 써야 한다.** `esp_bt_controller_init()` 직접 호출은 상태가 IDLE 로
  읽히는데도 `ESP_ERR_INVALID_STATE` 를 돌려준다.
- **큰 버퍼는 전부 PSRAM.** 내부 DRAM 은 320KB 뿐이고 BT+WiFi 스택이 먹는다.
  `MALLOC_CAP_INTERNAL` 은 IRAM 을 줄 수 있는데 IRAM 은 16비트 접근이 불법이다.
- **SD 는 1비트 모드.** 4비트는 GPIO13 을 먹어 KEY2 와 부딪힌다.
- **LED 핀을 키보다 먼저 설정한다.** 안 하면 GPIO13(KEY2)이 GPIO22 에 끌려 LOW 로 읽힌다.
- **GPIO16/17 은 PSRAM 것이다.** 만지면 즉시 재부팅 루프.
- **음량은 A2DP 콜백에서 곱한다.** 디코더에서 곱하면 링버퍼 깊이(약 1.5초)만큼 늦게 반응한다.
- **링이 절반 찬 뒤에 스트림을 시작한다.** 시작 직후 언더런을 피한다.
- **타입은 `player.h` 에 둔다.** arduino-cli 가 `#include` 직후에 함수 원형을 자동 삽입해서,
  .ino 본문에 정의한 struct 를 인수로 받는 함수는 "does not name a type" 으로 깨진다.
- **`partitions.csv` 의 플래그 칸 뒤에 주석 금지.** arduino-cli 가 주석을 플래그로 읽고 죽는다.
