# 음향 폐루프 자기진단 — 그리고 오디오가 막힌 이유

사람이 보거나 듣지 않아도 오디오 경로를 판정한다. 보드가 스스로 음을 내고 자기
마이크로 들으면 되기 때문이다.

핵심은 **동기 검파**다. 낸 주파수의 sin/cos 과 곱해 적분하면 노이즈 플로어보다 훨씬
아래의 신호도 잡힌다. 그냥 RMS 를 보면 "조용해서 안 들림" 과 "경로가 죽음" 이
구분되지 않는다 — 실제로 이 함정에 한 번 빠졌다(같은 설정이 1초 측정에서 피크 63,
400ms 에서 피크 1).

## 결론: I2S 오디오가 흐르지 않는다

```
[1] 기준선 (무음)        검파 L 0.00  R 0.00   RMS L 1.0  R 1.0
[2] 음 출력, GPIO22=LOW  검파 L 0.00  R 0.00   RMS L 1.0  R 1.0
[3] 음 출력, GPIO22=HIGH 검파 L 0.00  R 0.00   RMS L 1.0  R 1.0
```

RMS 1.0 은 LSB 노이즈 수준, 즉 완전한 0 이다. `mic_node` 에서 관측된 "L 피크 63" 은
실제 오디오가 아니라 순간 노이즈였다.

## 소프트웨어로 시도한 것 전부

| 시도 | 결과 |
| --- | --- |
| AC101 I2C 통신 | **정상** — 레지스터 쓰기·읽기 양방향 확인 |
| ADC 경로 레지스터 | **정상 설정** — `DIG=0x8000 APC=0x3BC0 SRC=0x2020` (읽기로 검증) |
| I2S DIN 후보 8개 (35/34/39/36/23/22/19/18) | 전부 무신호 |
| `ADC_SRC` 후보 9개 | 전부 무신호 |
| `ADC_APC_CTRL` 후보 9개 | 전부 무신호 |
| `MODE_ADC` / `MODE_ADC_DAC` | 둘 다 무신호 |
| `use_apll` on / off | 둘 다 무신호 |
| 라이브러리 `MODE_ADC` 미완성 버그 수정 | 필요했지만 이것만으로는 부족 |

**코덱과는 완벽하게 대화가 되는데 오디오 데이터만 안 흐른다.** 이 조합이 남기는
결론은 하나다.

## 남은 단일 용의자: 가운데 DIP 스위치

`docs/HARDWARE.md` 에 첫 조사부터 적어 둔 미확인 항목이다 — 여러 기능이 공유하는
GPIO 를 microSD 쪽으로 붙일지 다른 쪽(JTAG/키)으로 붙일지 갈라주는 물리 점퍼이고,
리비전마다 매핑이 다르다. 이게 I2S 또는 마이크 라인을 끊어놓으면 **정확히 이 증상**이
난다: I2C 는 멀쩡하고(별도 버스) 오디오만 0.

물리 스위치라 코드로 바꿀 수 없다.

## 그래서 무한 감시로 남겨 뒀다

이 펌웨어는 1초에 한 번씩 폐루프 테스트를 반복하며 로그를 찍는다. **아무 때나 DIP
스위치를 딸깍거리면 오디오가 살아나는 순간이 로그에 남는다** — 지켜볼 필요가 없다.

```
[  12] 검파 L    0.00 R    0.00  RMS L    1.0 R    1.0  무신호 (DIP 스위치를 딸깍거려 보세요)
...
*** 오디오가 살아났다! DIP 스위치가 원인이었다 ***
[  47] 검파 L  812.40 R  790.11  RMS L  980.2 R  965.7  ◀◀ 신호 있음
```

읽는 방법:

```bash
python3 - <<'PY'
import serial, time
s = serial.Serial('/dev/ttyUSB0', 115200, timeout=0.3)
t = time.time(); buf = b''
while time.time() - t < 10: buf += s.read(4096)
print(buf.decode('utf-8', 'replace'))
PY
```

## 이 보드에서 확인된 것 / 안 되는 것

**되는 것** — ESP32 자체는 온전하다. PSRAM 4MB, 플래시 4MB, 듀얼코어, WiFi, BLE,
I2C(GPIO32/33), GPIO, 그리고 온디바이스 추론(numpy 참조와 오차 1.27e-07 일치).

**안 되는 것** — I2S 오디오 입출력. 그래서 스피커·마이크를 쓰는 프로젝트는 전부 막힌다:
번역 무전기(`cabin_node`), 악기(`synth_node`), 2마이크 센서(`mic_node`).

세 펌웨어 모두 빌드·플래시·수치 검증까지는 끝나 있다. 오디오 배선만 풀리면 바로 돈다.
